## 2. 契约明细（openapi-m2-8，27 路径）

### 2.1 `POST /api/v1/telemetry/batch`（前端唯一需要关心的端点）

- 请求体：`{ "events": TelemetryEvent[] }`，每事件 `{event, ts, run_id?, page?, props?}`，与 WP-18 现有发送形态逐字段一致。
- 成功：**204 无响应体**；响应头 `X-Accepted-Events: <n>` 仅供后端调试，前端不要依赖。
- 批级 422：`events` 不是数组/空数组/超过 200 条/缺 event 或 ts/类型错误（FastAPI 422，body `detail`）；raw body 超 64KB 返回 422 `{code:"telemetry_batch_invalid"}`。WP-18 单批最多 5 条，正常不会命中。
- 超频：429 `{code:"telemetry_rate_limited"}`（>12 批/用户/分钟）。
- **条级容错（关键，与前端队列重试的关系）**：单条事件 event 非法字符、ts 超出 ±7 天、page/run_id 超长、props 含嵌套对象/数组/null/超 256 字字符串/键超限等，**只丢该条，其余照收，整批仍 204**；全部非法也 204。前端无需为单条坏数据做任何处理，坏队列不会因 422 卡死反复重试。

### 2.2 props 隐私白名单

只收扁平标量（string/int/float/bool）；键名 `^[a-z0-9_]{1,64}$`、≤20 键、字符串值 ≤256 字。WP-18 现有三事件 props（intent 枚举/耗时/degrade_reason、intervene 的 action/result/error_code、citation 的 evidence_id）全部合规。**不要**往 props 加问题原文、澄清答案、token 等自由文本——会被服务端整行丢弃。

### 2.3 `GET /api/v1/telemetry/metrics?from=&to=`（本批前端无 UI）

登录可读，返回窗口内全局聚合标量（无明细/无 user/team 维度），默认近 30 天、最大 90 天。结构（供后续运营页参考，WP-18 不消费）：

```jsonc
{
  "window": {"from": "...", "to": "..."},
  "runs": {"total_terminal": 42, "succeeded": 36, "failed": 2, "cancelled": 4, "success_rate": 0.947},
  "intervention": {"runs_started": 50, "runs_with_intervention": 11, "intervention_rate": 0.22,
                   "by_action": {"pause": 3, "resume": 1, "followup": 2, "exclude": 4, "clarify": 1}},
  "traceability": {"final_reports": 36, "avg_numeric_binding_rate": 1.0,
                   "runs_with_citation_open": 30, "citation_open_rate": 0.833, "citation_open_events": 214},
  "intent": {"classify_total": 130, "degraded": 5, "degraded_rate": 0.038},
  "ingest": {"accepted_events": 1520, "dropped_events": 3, "rate_limited_batches": 0}
}
```

口径要点：成功率分母 succeeded+failed（cancelled 排除、无样本为 null）；介入率分子只信业务表（run_interventions applied + run.pause/run.resume 审计按 run 去重），`clarify` 计数取自前端 cockpit.intervene 成功事件（澄清提交复用 resume 通道，业务表无法拆分）；溯源率为 final 报告机器绑定率均值 + report.citation.open 的 distinct run 交互口径双值。
