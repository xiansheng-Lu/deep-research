## 0. 本次对接结论（TL;DR）

1. 五个看板只读 GET + `GET /api/v1/runs` 列表全部就绪；阶段行随执行实时落库，**运行中（未终态）看板 REST 即可读到真实数据**（每个 super-step 一次中间提交，AC-12）。
2. 前端 mock 先行的五类客户端与实时帧类型已就位，路径/信封/帧类型与后端冻结契约**破坏性差异 0**；仅有 2 处增量要补：
   - `CostSnapshot` 类型补 `level` 字段（REST 快照新增；WS `cost.warning` 帧的同名字段前端已有）；
   - 新增 `GET /runs` 列表客户端（关闭 R3「进行中研究」卡片本地索引），前端目前只有 POST 创建与 GET 详情。
3. `stage.finished` 后端 payload 是前端声明类型的超集（多 `status/duration_ms/token_used`），不补类型也不破坏，需要展示阶段耗时/分段 token 时可直接消费。
4. 证据全文 `content` 本包通常为 `null`（检索链只存 500 字 snippet），前端以 snippet 兜底的既有策略不变；详情端点路径与 mock 先行形态完全一致，`getEvidence` 无需改。
5. 联调必须 `VITE_MOCK=off`；M2-2 交接单 §7.4 登记的「看板 GET 真链 404、allSettled 静默兼容」现象随本次上线消失。

## 2. REST 契约（已冻结，逐字段见 openapi-m2-4.json）

### 2.1 本批新增端点一览

| 方法与路径 | 响应 | 排序/口径 |
| --- | --- | --- |
| GET `/api/v1/runs` | `PageEnvelope<RunResponse>` | 创建者维度；`status`（六态单值，非法值 422）、`project_id`（非本团队项目 404）、`page`≥1、`page_size` 1~100（超限 422）；created_at DESC, id ASC |
| GET `/api/v1/runs/{run_id}/stages` | `StageResponse[]` | 固定六阶段顺序（clarify→decompose→retrieve→standardize→critique→report）；历史无阶段行 run 返回 `[]`，不报错 |
| GET `/api/v1/runs/{run_id}/sub-questions` | `SubQuestionResponse[]` | created_at ASC, id ASC |
| GET `/api/v1/runs/{run_id}/evidence` | `PageEnvelope<EvidenceResponse>` | fetched_at DESC, id ASC；默认剔除 `excluded_by_user=true`，`include_excluded=true` 带出；`sub_question_id` 跨 run → 404 |
| GET `/api/v1/runs/{run_id}/evidence/{evidence_id}` | `EvidenceResponse` | `content` 全文通道（本包通常 null）；归属不符 404 |
| GET `/api/v1/runs/{run_id}/cost/snapshot` | `CostSnapshotResponse` | running/paused 态即真实值；见 §2.2 |

分页信封为扁平 `{items,total,page,page_size,has_more}`，与前端 `PageEnvelope<T>` 一致；`/runs` 同路径含 POST（M1 创建）+ GET（本批），共享 `/api/v1/runs` 路径对象。

### 2.2 成本快照与 level 派生（重点）

```jsonc
{
  "used": 700,
  "budget": 1000,
  "ratio": 0.7,
  "level": "warning"   // <0.7 为 null；≥0.7 "warning"；>0.9 "danger"（边界：0.9 仍为 warning）
}
```

- `ratio` 恒为 float；`budget=0` 时按 0.0 处理（非 null）。
- level 阈值与 WS `cost.warning` 帧、90% 挂起条件边同源配置，三处口径不会漂移。

### 2.3 StageResponse 字段口径

`id, run_id, name, status, attempt, started_at, finished_at, created_at, updated_at`。**不输出** `token_used/error_code/output`：失败原因走 `stage.failed` 帧与 run 详情，阶段 token 走成本域（阶段方案 §10 偏离点 8）。前端时间线类型已按此声明，无需改。

### 3.2 `src/services/api/runs.ts`：新增创建者维度列表客户端（R3 必改）

当前文件只有 POST 创建与 GET 详情。新增（建议同时在 types.ts 补查询参数类型，风格仿 `EvidenceListParams`）：

```ts
// GET /runs：创建者维度分页（M2-4，关闭首页"进行中研究"本地索引）
export function listMyRuns(params?: {
  status?: RunStatus
  project_id?: string
  page?: number
  page_size?: number
}): Promise<PageEnvelope<RunResponse>> {
  const search = new URLSearchParams()
  if (params?.status) search.set('status', params.status)
  if (params?.project_id) search.set('project_id', params.project_id)
  if (params?.page !== undefined) search.set('page', String(params.page))
  if (params?.page_size !== undefined) search.set('page_size', String(params.page_size))
  const query = search.toString()
  return http<PageEnvelope<RunResponse>>(`/runs${query ? `?${query}` : ''}`)
}
```

注意：这是**创建者维度**列表；项目维度 `GET /projects/{id}/runs` 属 M3，勿提前接。

## 4. 实时帧契约（不入 OpenAPI，沿用 envelope）

频道统一 `runs:{run_id}`，外层 `{type, run_id, stage?, payload}`，字段嵌套在 `payload` 内（M2-2 已踩过的帧 type 覆盖问题保持规避）。

| 帧 type | 发布点 | payload 关键字段 | 与前端类型核对 |
| --- | --- | --- | --- |
| `stage.started` | 执行器阶段切换 | `stage, attempt, token_used` | 一致 |
| `stage.finished` | 上行阶段收口（每超步中间提交前） | `stage, attempt, status:"succeeded", duration_ms:int, token_used` | 前端类型为子集（缺 status/duration_ms/token_used），**超集不破坏**；要展示阶段耗时可补可选字段 |
| `stage.failed` | 图执行异常收口当前阶段 | `stage, attempt, status:"failed", error_code, error_message, retryable:false` | 与 `StageFailedPayload` 一致 |
| `sub_question.created` | decompose（quick 降级为单子问题同样发） | `sub_question_id, question, status:"pending", depends_on` | 一致 |
| `sub_question.started` | retrieve fan-out 每层调度前 | `sub_question_id, status:"running"` | 一致（started 不带 question） |
| `sub_question.finished` | 每条检索回写后 | `sub_question_id, status, evidence_count`；空结果 `status:"evidence_short"`、异常 `status:"failed"` 如实携带 | 一致 |
| `evidence.fetched` | **standardize 分类落库后**（非 retrieve 当时） | 证据列表展示字段（无 content），含最终 `source_level/credibility` | 与 `EvidenceFetchedPayload` 一致；重放不重发 |
| `token.usage.update` | 执行器逐超步，1s 节流，用量未变不发，终态/挂起强制补发 | `used, budget` | 一致（model_breakdown 可选不输出） |
| `cost.warning` | 跨阈值边沿，每级至多一帧，单跳越 90% 只发 danger | `level, used, budget, ratio` | 与 `CostWarningPayload` 一致 |

时序要点（方案 §5）：帧可能先于事务提交到达，帧 payload 可直接渲染，REST 定位为初帧/重连补偿；前端 live 后 `alignWithRest` 与既有 retrying 轮询策略保持不变。evidence.fetched 延后到 standardize 是有意设计（避免先渲染临时 tertiary/C 再跳级，方案 §10.2）。

4. **真实后端无 `POST /telemetry/batch`（404）**：WP-18 前端埋点按契约静默失败、不阻塞页面（后端日志可见 404），端点上线后自动生效，与本单无关，仅同步现象。
5. **mock gateway 暂无 `GET /runs` 列表路由**：mock 下首页活跃卡静默为空（404 不触发本地索引兜底、无错误态）；不影响既有只读页面，后续 mock 维护时建议补该路由以便无后端开发演示。
6. 环境备注：本机为 WSL2 NAT 模式，Windows 侧 localhost 到 WSL 端口转发不通，Vite 代理用 `VITE_API_BASE=http://172.30.1.227:8000`；后端在 WSL 内 `uv run` 直连容器 localhost 映射。

### 8.4 结论

交接单两处必改（CostSnapshot.level、listMyRuns）与 R3 首页接线均已完成；可自动化的 REST/WS/错误路径/门禁项全部通过，3 项依赖真实 LLM 产出或失败注入的浏览器侧项未构造样本，建议按本单 §7.2 由后端抽验确认后关闭归档。
