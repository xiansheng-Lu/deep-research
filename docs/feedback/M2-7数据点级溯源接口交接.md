### 2.2 两报告端点响应超集

`outline: ReportOutlineItem[]`（`{id,title,type}`，2~4 条）：

- 固定 `sec-overview 调研概述`(conclusion)、`sec-findings 核心发现`(conclusion)；
- `sec-disputes 分歧与不确定性`(dispute) 仅当存在分歧块；
- `sec-limitations 局限与建议`(limitation) 始终至少一条（LLM 未产出时后端兜底）。

`blocks: ReportBlock[]`，与前端类型同构：

| type | 携带字段 |
| --- | --- |
| `conclusion` | id/type/text/claim_id/**confidence**/citations |
| `evidence` | id/type/text/citations（无 claim_id、无 confidence） |
| `dispute` | id/type/text/**claim_id**/**conflict_id**/**confidence**/citations |
| `limitation` | id/type/text/citations（无 claim_id、无 confidence） |

内联 `citations` 元素为三字段 `{evidence_id, marker, snippet}`；`confidence` 三值 `single_source/cross_verified/inferred`（中文标签 WP-16 已实现）。

字段名/枚举/可选性已与 `frontend/src/services/api/types.ts` 逐字段核对，**差异为 0**；block.id 后端终稿恒有值（前端可选声明不拒绝）。draft/历史报告 `outline=[]、blocks=[]`。

## 3. 终稿数据行为（解释异常渲染）

1. **marker 仅被引证据占号**：按材料池顺序（跨子问题、可信度→相关性）为**被引用到的**证据编号，未被任何 block 引用的证据不占号、不在 citations 端点返回；真链信源条数 ≤ 证据总数。与 fixture「全量占号」不同（demo 12 条恰好全被引，输出碰巧一致）。
2. **snippet 两级粒度**：LLM 提供 quote 且在 trafilatura 正文中命中 → 取原句窗口（约 120 字，最细粒度）；未提供/正文缺失/不命中 → 回证据检索摘要。两种情况引用都保留，回溯不损。
3. **100% 绑定硬指标**：含数字/百分比/金额/年份等数据点的 conclusion 无引用时，后端做一次整份自修复；仍无引用的数字块直接从终稿剔除（不冒充事实）；无数字的无来源结论强制降级 `inferred` 保留。内部审计在 `content_json.citation_audit`（不进响应）。
4. **dispute 块后端确定性注入**：待裁决冲突与 both/reject 保留分歧各一块，强制挂双方/存活方证据与 `conflict_id`；双方证据均被用户剔除时该冲突不出块（仍可在分歧列表端点查看）。
5. **终稿 status=final**：取消运行保留的部分稿仍为 draft（旧 content_json 形态、blocks/outline 空、无引文）。
