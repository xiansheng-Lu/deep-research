## 0. 本次对接结论（TL;DR）

1. WP-15 依赖的四个 REST 控制点全部就绪，此前 mock 模拟的 pause/resume/cancel/intervene 真链 404 现象消失：`POST /api/v1/runs/{id}/pause`、`/resume`、`/cancel`、`/intervene`。
2. WS 通道新增 `intervene` / `cancel` 客户端指令，与 REST **复用同一 service**，回 `intervene.ack` / `intervene.error`，`request_id` 原样透传；pause/resume **无 WS 指令**，只走 REST（与前端 `ClientCommandType` 声明一致）。

5. 前端 `types.ts` / `realtime/types.ts` 预置的请求体、响应、ACK 信封与冻结契约**逐字段核对差异为 0**（本单 §3.1）；`revert_stage` / `mark_doubt` 前端联合类型里保留但 M2 不开放，后端对其 422。

## 2. REST 契约（已冻结，逐字段见 openapi-m2-5.json）

### 2.1 本批新增端点一览

| 方法与路径 | 请求体 | 200 响应 | 主要拒绝 |
| --- | --- | --- | --- |
| POST `/api/v1/runs/{run_id}/pause` | `{reason?: string(≤256)}` | `RunControlResponse{run_id,status:"paused"}` | 409 `RUN_NOT_PAUSABLE`（非 running/在途无协程的孤儿 running）、409 `RUN_ALREADY_PAUSED` |
| POST `/api/v1/runs/{run_id}/resume` | `{human_input?: HumanInput}` | `RunControlResponse{run_id,status:"running"}` | 409 `RUN_NOT_RESUMABLE`；422 三分支互斥/澄清缺答案 |
| POST `/api/v1/runs/{run_id}/cancel` | `{reason?: string, keep_partial?: bool=true}` | `RunControlResponse{run_id,status,partial_report_id?}` | 终态幂等返回实际 status，不改状态、不重复发帧 |
| POST `/api/v1/runs/{run_id}/intervene` | `InterventionAction{type, payload}` | `RunControlResponse{run_id,status}` | 409 `INTERVENE_NOT_ALLOWED`；422 载荷非法；404 引用资源跨 run/不存在 |

业务判别码位置与 M2-2 裁决 409 同一形态：HTTP 信封 `{code:"conflict", message, details:{code:"RUN_NOT_PAUSABLE", ...}}`，前端按 `details.code` / message 映射（mock 预置的映射不变）。

### 2.2 状态机与允许矩阵（重点）

```text
pending ──首跑──▶ running ──pause──▶ paused ──resume──▶ running
                    │  ▲              │  ▲
        澄清/裁决/成本挂起(已有路径)   │  └────cancel────▶ cancelled
                    │                │
                    └────cancel───────┘
running/paused ──cancel──▶ cancelled（终态，不可恢复）
```

| 端点 \ 当前状态 | pending | running | paused | succeeded/failed | cancelled |
| --- | --- | --- | --- | --- | --- |
| pause | 409 RUN_NOT_PAUSABLE | 200 | 409 RUN_ALREADY_PAUSED | 409 | 409 |
| resume | 409 | 409 RUN_NOT_RESUMABLE | 200 | 409 | 409 |
| cancel | 200 | 200 | 200 | 200 幂等 | 200 幂等 |
| intervene ask_followup | 409 | **仅 current_stage=retrieve** | 409 | 409 | 409 |
| intervene exclude_evidence | 409 | current_stage ∈ retrieve/standardize/critique | 409 | 409 | 409 |

### 2.3 时序收敛口径（pause/cancel 必读）

- pause/cancel 的 REST 200 **先返回**，执行协程在下一 await 点（super-step 边界）才落库收尾；极端竞态下 `GET` 可能瞬时读到旧状态。最终状态以随后到达的 `run.finished(status=paused/cancelled)` 帧 + GET 详情收敛——与 M2-2 起「帧为最终收敛」的既有模式一致，前端不要只凭 200 响应渲染终态。
- pause 后当前阶段行**保持 running**（不新增 stage cancelled/paused 枚举），run 终态是唯一事实；`finished_at` 不置位。
- cancel 置 `cancelled` + `finished_at`；`keep_partial=true` 且存在报告草稿时 200 带回 `partial_report_id`（M2 报告为一次性确定性拼装，多数取消点无草稿，字段缺省是正常态）。
- running 行但进程内无在途协程（API 重启孤儿）时 pause 返回 409，不假成功；孤儿清扫在 M2-8。

### 2.4 resume：HumanInput 三分支

```jsonc
// 三选一互斥（同时出现多个键 422）；空 body 等价 {"human_input":{"kind":"proceed"}}
{
  "answers": { "scope": "近三年", "verdicts": {"conf_...": {"choice":"evidence_a","reason":"..."}} },
  "action":  { "type": "ask_followup", "payload": {"sub_question_id":"...", "question":"..."} },
  "kind": "proceed"
}
```

| 挂起原因 | 允许输入 | 行为 |
| --- | --- | --- |
| clarify | 仅 `answers`（≥1 个非空答案键，verdicts 不计入） | 合并为 state.clarification 回流，**不二次挂起**；空 answers/proceed → 422 |
| critique（high 冲突挂起） | `answers.verdicts` 或 proceed | 裁决主通道仍是 `/conflicts/{id}/verdict`，本分支仅统一入口完整性 |
| cost（user_intervention） | `kind=proceed` 或空 body | 空节点 → report，即 M2-4 成本闸门实测恢复路径 |
| 手动软暂停 | `kind=proceed` 或空 body | 从最近 checkpoint 续跑当前阶段 |

`action` 分支经统一 resume 入口返回 409 `INTERVENE_NOT_ALLOWED`（running/paused 介入统一走 `/intervene`，paused 不支持补查）。

### 2.5 intervene：动作语义

- `ask_followup`：payload `{sub_question_id(必填,本 run 子问题), question(1~1000 字非空), reason?}`；run 保持 running，动作入 `run_interventions` 队列（pending），fan-out **下一层边界**消费：新建子问题（depends_on 指向原子问题）并发 `sub_question.created/started/finished`，追加证据进同一份报告。
- `exclude_evidence`：payload `{evidence_id(必填,本 run 证据), reason?}`；**同步**置 `excluded_by_user=true` 并提交（看板 REST 立即生效），介入行直接记 applied；剔除发生在 retrieve 时证据不进 standardize；standardize/critique 时 critic 冲突输入与 reporter 论断均不再含该证据；**已落库冲突/已生成报告不追溯**。
- 幂等：REST 可选 `Idempotency-Key` 请求头（≤64 字符），双击只入队一次、返回同一 200；**WS 指令无此头，不启用服务端幂等**（前端按钮防抖兜底）。
- 404：`sub_question_id` / `evidence_id` 不存在或跨 run（与归属同口径，不区分「不存在」与「他人的」）。

### 2.6 RunResponse 增量（超集，可选字段）

```jsonc
"interrupt": {
  "reason": "clarify",
  "questions": [{"key":"scope","text":"...","options":[],"recommended":null}],
  "defaults": {},
  "expires_in_seconds": 900
} // 仅 paused@clarify 非空；其余状态/非澄清挂起恒为 null
```

## 3. WS 控制指令与实时帧（不入 OpenAPI）

频道与信封不变：频道 `runs:{run_id}`，推送信封 `{v,event_id,ts,run_id,stage,type,payload}`。

### 3.1 客户端指令（连接内，复用 REST 同一 service）

发送（前端 `sendCommand(type, payload)` 既有形态）：

```jsonc
{"v":"1.0","type":"intervene","request_id":"req-1","payload":{"type":"ask_followup","payload":{"sub_question_id":"...","question":"..."}}}
{"v":"1.0","type":"cancel","request_id":"req-2","payload":{"reason":"...","keep_partial":true}}
```

应答（两类指令共用同一对帧名，与前端 `InterveneAckEnvelope`/`InterveneErrorEnvelope` 一致）：

```jsonc
{"v":"1.0","ts":1757800000000,"type":"intervene.ack","request_id":"req-1","payload":{"status":"running"}}
{"v":"1.0","ts":1757800000000,"type":"intervene.error","request_id":"req-2","payload":{"code":"INTERVENE_NOT_ALLOWED","message":"..."}}
```

- 成功 `payload.status` 即 run 当前状态（cancel 成功为 `cancelled`；不在 WS ACK 带回 partial_report_id）。
- 错误码就是业务判别码本身（无 HTTP 层 `details` 嵌套）：`INTERVENE_NOT_ALLOWED` / `INVALID_ACTION_PAYLOAD` / `RUN_NOT_RESUMABLE` / `not_found` / `auth_error` / `UNKNOWN_COMMAND` / `internal_error`。
- 缺少 `request_id` 的消息被忽略（无关联键，不回帧、不断连）；未知 type 回 `UNKNOWN_COMMAND`；指令处理异常回 error 帧且**不断开连接**；非法 JSON 丢弃保活。
- WS 指令不带来超出 REST 的能力，仅省一次 HTTP；双发竞态由同一 service + 条件 UPDATE 状态机收敛。

### 3.2 实时帧增量

| 帧 type | 时机 | payload | 与前端核对 |
| --- | --- | --- | --- |
| `interrupt.requested` | clarify 挂起落库后、`run.finished(paused)` 前 | `{reason:"clarify", questions[], defaults, expires_in_seconds}`，question 项 `{key,text,options,recommended}` | 与 `InterruptRequestedPayload` / `ClarificationQuestion` 一致 |
| `run.finished`（复用） | pause/cancel 协程收尾 | 既有 RunFinishedPayload，`status` 新增合法值 `"paused"` / `"cancelled"`（前端联合类型已含） | 已含，无新帧 |
| `sub_question.created/started/finished`（复用） | followup 补查 | 既有 M2-4 形态 | 已含 |

不新增 `run.paused` / `run.resumed` 独立帧：paused 由 `run.finished(paused)` 承载（M2-2 冻结口径），resume 后续跑由 `stage.started` 表达。`interrupt.requested` 不做服务端回放，刷新恢复走 §2.6 的 REST `interrupt` 字段。

## 4. 前端对接要点

### 4.1 无需改类型（已逐字段核对，差异 0）

- `PauseRunRequest` / `CancelRunRequest` / `HumanInput`（answers/action/kind）/ `InterventionAction`（type 枚举 ask_followup/exclude_evidence）/ `RunControlResponse`（run_id/status/partial_report_id?）与 openapi-m2-5 一致；
- `ClientCommand` / `InterveneAckEnvelope` / `InterveneErrorEnvelope` / `CommandAck` 与 §3.1 一致；
- `InterruptRequestedPayload`、`ClarificationQuestion` 与 §3.2 一致；
- `RunResponse` 需在前端类型补可选 `interrupt?: InterruptRequestedPayload | null`（若刷新恢复澄清卡走该字段；以本地实际声明为准核对，mock 先行未声明则补可选，不破坏既有消费）。

### 4.2 行为接线提醒

- 四个 mock 模拟端点切真实 HTTP 客户端（`services/api/`），错误映射读 HTTP 体 `details.code`；WS 指令错误读 payload.code（两处码名相同、层级不同）。
- pause/cancel 按钮的最终态以 `run.finished` 帧收敛，不要只以 200/ACK 翻转终态 UI；暂停后阶段行仍 running 是预期。
- WS 握手现在可能因归属被 1008 拒（含 token 用户被注销），重连/错误提示沿用既有通道关闭处理。
- 剔除证据为**单向**操作：本包不提供恢复接口（mock 中 `excluded:false` 的恢复语义为 mock 先行形态，真链不要调用）。
- `expires_in_seconds` 仅展示；澄清答案必须真实提交，不提供「按默认继续」按钮（空答案后端 422）。

## 6. 联调自测清单（前端回归时勾选）

**类型与构建**

- [ ] `RunResponse.interrupt` 可选字段补齐后 `npm run typecheck` 通过；`npm run lint` / `npm run build` 无新增告警。

**真实链路（重点 AC-1~AC-5、AC-8、AC-9、AC-11）**

- [ ] AC-1 pause：running 中点暂停 → 200 paused → 收到恰好一帧 `run.finished(paused)`，阶段行保持 running、token 为真实值；已暂停再 pause 409 RUN_ALREADY_PAUSED；终态 pause 409。

- [ ] AC-3/AC-4 cancel：running 取消 → 200 + `run.finished(cancelled)`，重复 cancel 幂等返回 cancelled；cancel succeeded run 返回 200 status=succeeded 不改状态；有草稿时 partial_report_id 可 GET。
- [ ] AC-5 澄清联通：真 LLM 触发澄清挂起 → `interrupt.requested` 帧渲染卡片 → resume 带 answers 后一路 succeeded 不二次挂起；刷新页面后 GET 详情的 interrupt 字段恢复卡片，恢复后为 null；空 body resume 澄清挂起 422。
- [ ] AC-6 成本挂起：90% 挂起后空 body resume → user_intervention → report → succeeded（M2-4 链路不回归）。
- [ ] AC-8 ask_followup：retrieve 中发起 → 200；下一 fan-out 边界出现新子问题层（created/started/finished 齐、证据落库），报告含追加证据；非 retrieve 阶段 409；跨 run 子问题 404；空白 question 422。
- [ ] AC-9 exclude_evidence：retrieve/standardize/critique 剔除立即生效（看板默认列表不含、include_excluded=true 可带出），报告结论不含该证据；report 阶段 409；跨 run 证据 404。
- [ ] AC-10 幂等：同 Idempotency-Key 双击只产生一条介入、一次补查，返回同一 200。
- [ ] AC-11 WS：连接内发 intervene/cancel 收到同 request_id 的 ack/error；错误动作回 INTERVENE_NOT_ALLOWED error 帧且连接不断；token 合法但非创建者握手被 1008 拒；pause WS 指令回 UNKNOWN_COMMAND（走 REST）。
