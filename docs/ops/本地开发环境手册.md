# AI 研究者助手 · 本地开发环境手册

> 本文档记录本项目本机开发环境的完整资源构成与日常运维操作，包括环境拓扑、资源配额、中间件、连接信息、运维命令、保活机制与故障排查；所有版本号、端口、配额与占用数据均为 2026-09-11 在开发机上实测所得。
> 适用场景：Windows 低内存开发机，以 WSL2 Ubuntu 作为 Linux 服务器运行 Docker 中间件，前后端进程运行在 Windows 宿主侧。
> 维护约定：本文档为活文档，环境相关变更（中间件版本、端口、配额、镜像、启动方式等）须在同一变更中同步更新对应章节，并刷新文首实测日期。

## 1. 环境拓扑

### 3.2 WSL 资源配额

配置文件位置：`C:\Users\Lenovo\.wslconfig`

```ini
[wsl2]
memory=5GB
processors=4
swap=1GB

[experimental]
autoMemoryReclaim=dropcache
```

| 资源 | 配额 | 说明 |
| --- | --- | --- |
| 内存 | 5GB（机内可见 4.8GiB） | 中间件稳态占用约 0.9~1.3GB，余量留给文件缓存与迁移尖峰 |
| CPU | 4 核 | 物理机共 12 核以上，其余留给 IDE、前端 Node 与 Windows |
| Swap | 1GB | 尖峰安全垫，实测稳态零使用 |
| autoMemoryReclaim | dropcache | 空闲时回收 Linux 页缓存并归还 Windows |

注意事项：

- WSL 2.7.13 实测不再识别 `pageReporting` 键，写入会在冷启动时报“未知键”警告，故不配置；页回收在新版中默认生效。
- `autoMemoryReclaim` 在本版本仍必须放在 `[experimental]` 段，放在 `[wsl2]` 段会报警告。
- 修改配置后执行 `wsl --shutdown` 冷启动生效，不影响磁盘数据。

## 7. 日常运维命令

以下命令均在 WSL（Ubuntu）内执行，可从 Windows 终端输入 `wsl -d Ubuntu` 进入。

```bash
# 启动中间件栈
cd /mnt/d/trae/product/deep-research/backend
docker compose -f docker-compose.dev.yml up -d

# 查看状态与健康检查
docker ps
docker stats --no-stream

# 查看日志
docker logs -f dr_postgres
docker logs -f dr_redis
docker logs -f dr_minio

# 停止 / 重启
docker compose -f docker-compose.dev.yml stop
docker compose -f docker-compose.dev.yml restart

# 重建 MinIO 后重新建桶（临时 mc 容器复用 minio 网络）
docker run --rm --network container:dr_minio --entrypoint /bin/sh minio/mc \
  -c 'mc alias set v http://127.0.0.1:9000 minioadmin minioadmin && mc mb --ignore-existing v/deep-research'
```

Windows 侧管理 WSL：

```powershell
wsl -l -v          # 查看发行版与运行状态
wsl --shutdown     # 关闭全部 WSL 虚拟机（使 .wslconfig 生效 / 回收内存）
```

## 8. 持久化与保活机制（重要）

WSL2 的生命周期特性：当最后一个 WSL 会话退出后，虚拟机会在约 8~16 秒后被自动回收，dockerd 随之优雅关闭，容器停止（属正常 fast shutdown，不是崩溃）。

本机已落地的两层应对：

1. 三个容器已设置 restart 策略为 `unless-stopped`（通过 `docker update` 设置，未改动仓库 compose 文件）。任何 WSL 虚拟机启动、systemd 拉起 dockerd 后，容器会自动恢复。
2. 日常开发保持至少一个 WSL 终端打开即可保活虚拟机。

边界说明：

- 电脑重启后，打开任意 WSL 终端触发虚拟机启动，三个中间件即自动恢复，数据不丢失。
- 若执行 `docker compose up` 重建了容器，restart 策略会重置，需重新执行：
  `docker update --restart unless-stopped dr_postgres dr_redis dr_minio`
- 数据卷位于 ext4.vhdx 内，`wsl --shutdown` 与容器重建（不带 -v）均不影响数据；`docker compose down -v` 会删除数据卷。

## 9. 已知提示与故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 每次启动 WSL 提示“检测到 localhost 代理配置，但未镜像到 WSL” | Windows 开启了 Clash（127.0.0.1:7897），NAT 模式不共享 localhost 代理。不影响国内 apt 源与 Docker 镜像加速；若 WSL 内需访问被墙资源，可开启 Clash 的允许局域网连接并放通防火墙，或将 .wslconfig 设为 networkingMode=mirrored |
| docker 命令报 permission denied | 用户未在 docker 组中或组权限未刷新；已执行 usermod -aG docker lenovo，新开 WSL 会话即可 |
| docker 客户端报 ~/.docker/config.json 解析错误 | 文件被写入 UTF-8 BOM；已修复为无 BOM 的 {} |
| 拉取 Docker Hub 镜像超时 | 确认 /etc/docker/daemon.json 中 registry-mirrors 生效（docker info 可见），必要时更换加速器地址 |
| Windows 侧连不上 localhost:5432 等端口 | 先 `wsl -l -v` 确认虚拟机处于 Running 且容器 healthy；WSL 停止后端口转发同步消失 |
