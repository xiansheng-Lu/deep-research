## 1. 阶段总览

按"打地基 → 开放价值 → GA"三段式推进：

| 段 | 里程碑 | 目标 | 关键产出 |
|---|---|---|---|
| **打地基** | M0 | 项目基础设施 + 底座 | 项目脚手架、多租户基线、Agent 编排引擎骨架 |
| **打地基** | M1 | 最小链路端到端 demo | 6 阶段流水线最小版 + 单次研究可走通 |
| **打地基** | M2 | 能力补齐与工程化 | 意图路由、批判收敛最小版、看板最简版、可观测性 |
| **开放价值** | M3 | 核心 MVP | MVP 功能全集、私域范围限定公域、首批内部试用 |
| **开放价值** | M4 | 体验打磨 | 看板增强、成本治理、报告精修、Word/PDF 导出、项目级权限 |
| **开放价值** | M5 | 私域能力 | 文档上传连接器、数据血缘、数据源级权限 |
| **GA** | M6 | SaaS GA | 公测开放、运营化体系、SLA 制定、私有化技术白皮书 |

**团队规模假设**：3-5 人全栈精英团队 + 1 产品。

**整体节奏建议**：
- M0~M2 各 4 周（压技术风险，每段都不能拖）
- M3 6 周（核心 MVP，需 2 轮内部反馈循环）
- M4 6 周（体验细节决定留存）
- M5 6 周（私域与企业权限是另一套工程）
- M6 4 周（公测与运营化）
- **合计 32 周**，自 M0 启动起算

> 上述节奏基于团队规模假设。若实际团队更小（如 3 人），需延长 20%-30%；更大则可压缩。

## 2. 阶段切分原则

三段式的内在逻辑（继承 SDP-Q1~Q9 决策）：

- **M0~M2 用"技术风险优先"切分**：先把多智能体编排、6 阶段流水线、Agent 契约这些"不确定能不能做"的部分用最小代价打通，避免技术风险延后暴露
- **M3~M5 用"用户可见价值"切分**：每阶段都产出用户能感知的能力，逐层从"能用"到"愿付费"
- **M6 用"运营化"切分**：把产品变成可持续运营的服务，附"私有化技术白皮书"作为长期能力背书

**核心交付节奏**：M1 末产出"最小可走通 demo"（内部演示价值）；M3 末产出"首批内测用户可用版本"（验证核心命题）；M5 末产出"企业版能力就绪版本"（启动企业销售）；M6 末产出"GA 版本"。

## 3. 里程碑详细规划

### M0 · 项目基础设施 + 底座（4 周）

**目标**：建立支撑后续 6 阶段流水线的工程底座，确保多租户、Agent 编排、模型调用层都有可复用的基础。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M0-1 | 项目脚手架 | 前后端代码仓库、CI/CD、测试框架、开发与预发环境 |
| M0-2 | 多租户基线 | 租户/用户/项目三层数据模型与权限中间件；MVP 仅用项目级权限 |
| M0-3 | 模型调用层抽象 | 统一封装模型 API（多家可替换）、调用日志、token 计量点 |
| M0-4 | Agent 编排引擎骨架 | LangGraph 等成熟框架底座（待技术选型评审）+ Agent 注册与发现机制 |
| M0-5 | 任务追踪基线 | `task_id` + `parent_task_id` DAG 模型、AuditLogger 雏形 |
| M0-6 | 基础文档骨架 | PRD、Agent 协作规格、SDP、本文件四份文档纳入版本管理 |

**关键依赖**：
- 技术选型评审（Agent 编排框架、模型供应商）必须在 M0 第 1 周完成
- 模型供应商合同/账号开通（依赖外部）

**验收准则**（必须全部通过）：
- 多租户数据模型支持"租户 → 用户 → 项目"三级隔离的单元测试通过
- Agent 编排引擎可注册、发现、调用一个示例 Agent，链路追踪日志完整
- 模型调用层成功接入 1 家模型供应商并能完成 prompt 往返 + token 计量
- CI/CD 流水线可在 PR 合并后自动部署到预发环境

### M1 · 最小链路端到端 demo（4 周）

**目标**：6 阶段流水线在单条研究任务上端到端可跑通，不追求质量与完整能力，只验证"流程能跑通"。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M1-1 | 6 阶段最简版实现 | Clarifier → SubQuestioner → Researcher → Standardizer → Critic → Reporter，每个 Agent 用最简 prompt 实现 |
| M1-2 | 单次研究走通 | 给定一个固定研究问题，全流程能产出非空报告 |
| M1-3 | 子问题并行机制 | Researcher × N 扇出，标准化的部分完成聚合策略 |
| M1-4 | 基础检索接入 | 公域网页抓取 + 简单去重，不做信源元数据完整抽取 |
| M1-5 | 报告最简呈现 | Markdown 文本输出，能渲染结论段落，不做交互 |
| M1-6 | 工程化补齐 | 失败可见、不静默；达到 token 预算 x% 停止；基本可观测性 |

**关键依赖**：
- M0 全部交付物就绪
- 公域检索抓取能力（自研爬虫或第三方 API）

**验收准则**（对应 PRD §11 验收项：**A1**，编号定义以 PRD §11 为唯一事实源，对齐关系见 §5.2）：
- 一个固定研究问题从输入到报告产出全程成功（手工冒烟）（A1）
- 6 阶段流水线在执行过程中每个阶段均有可见日志与状态
- Researcher 并行实例彼此独立，单实例失败不影响其他实例
- 达到 token 预算上限时自动停止，不超支（A6 的预算挡板前置能力在 M1 已具备，A6 整体在 M3 正式验收）
- 报告渲染至少能在 Web 端查看基本结论

### M2 · 能力补齐与工程化（4 周）

**目标**：把 M1 的 demo 升级为可被真实用户试用的最小完整产品——补齐意图路由、批判收敛、透明看板等 PRD 已定义的能力。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M2-1 | 意图路由 | 单入口 + 自动判别"闲聊/研究"；UI 给出"将走深度研究"提示与撤回选项 |
| M2-2 | 批判收敛最小版 | 全报告级批判 Agent，能收敛可调和冲突，显式呈现不可调和分歧 |
| M2-3 | 透明看板最简版 | 实时阶段进度 + 证据源列表 + 冲突提示，无成本展示与降级提示 |
| M2-4 | 编排层补齐 | Orchestrator 完整实现：依赖检测、回溯、降级、暂停接口 |
| M2-5 | 横切模块 | CostController、AuditLogger 完整版，token 实时计量与展示（仅内部） |
| M2-6 | 信源元数据抽取 | 来源域名/发布时间/类型/可信分级，去重打分（不实现"证据簇"自动聚类） |
| M2-7 | 数据点级溯源 | 报告内每个论断自动绑定信源与原文片段，UI 支持点击回溯 |

**关键依赖**：
- M1 全部交付物就绪
- 意图路由判别阈值标定（依赖内部评估集）

**验收准则**（对应 PRD §11 验收项：**A2、A3、A5、A8、A11、A12、A13、A14**，编号定义以 PRD §11 为唯一事实源，对齐关系见 §5.2）：
- 一句闲聊问题被路由到通用 LLM（不走 6 阶段流水线）（A11、A14）
- 一句研究问题被路由到 6 阶段流水线，UI 显示"将走深度研究"提示（A12、A13；不确定默认走研究且可撤回属 A13）
- 一次研究执行中，看板可实时显示当前阶段进度、已采集证据源数量与实时 token 用量（A5；token 实时计量与展示由 M2-5 交付，仅内部口径）
- 报告中每个论断可点击回溯到原始证据原文片段（A2），报告含"结论/证据/分歧/局限"四类区块（A3）
- 当存在不可调和冲突时，报告内显式呈现分歧而非隐藏（A3；冲突"可筛选查看"的完整验收在 M3，对应 A4）
- 一次研究全流程有完整审计日志可回放；溯源可回溯率、看板介入率、报告生成成功率埋点可出数（A8）

### M3 · 核心 MVP（6 周）

**目标**：MVP 功能全集就绪，可交付给首批内部/种子用户试用。验证"系统性+可信可溯源"这一核心命题。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M3-1 | MVP 功能全集 | 整合 M1+M2 能力，覆盖 PRD V1 范围（11 项核心功能） |
| M3-2 | 数据源限定公域 | MVP 仅公域检索，私域相关功能占位但不启用 |
| M3-3 | 档位参数化 | 快速/标准/深度/极致四档，检索轮数与 token 上限可配 |
| M3-4 | 领域模板最简版 | 通用模板 + 一个示范模板（如技术调研/竞品分析） |
| M3-5 | 基础运营体系 | 账号/邀请/反馈通道、问题收集看板 |
| M3-6 | 内部试用 | 5-10 个种子用户开始试用，收集反馈 |

**关键依赖**：
- M2 全部交付物就绪
- 种子用户沟通与试用协议
- 反馈分析机制（工单 + 调研）

**验收准则**（里程碑级硬指标）：
- 端到端研究耗时：标准档位下，单次研究从输入到报告产出 ≤ 15 分钟（`[待确认]`，需根据实测调整）
- 数据点溯源覆盖率：报告中**有数字或事实声明的论断** 100% 绑定信源；纯推论性段落允许标注"推断"
- 看板刷新延迟：用户视角 ≤ 3 秒
- 种子用户 NPS ≥ 30（`[待确认]`，MVP 阶段不作硬性商业指标）
- PRD §11 验收清单中归属 M3 的 A4、A6、A7、A9、A10 全部通过（M1 已通过 A1；M2 已通过 A2、A3、A5、A8、A11、A12、A13、A14；对齐关系以 §5.2 为准）

### M4 · 体验打磨（6 周）

**目标**：把 MVP 升级为"用户愿付费"的体验完整版。重点是看板、成本治理、报告精修、权限、导出。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M4-1 | 看板增强 | 加入实时成本展示、降级提示、暂停/追问/剔除证据的操作面板 |
| M4-2 | 成本治理完善 | 档位 token 上限可视化、超档降级流程、用户预算预警 |
| M4-3 | 报告精修 | 在线交互式报告完整版：点击回溯、筛选分歧、证据时间线/可信分级可视化 |
| M4-4 | Word/PDF 导出 | 报告导出结构化文档，支持企业内部汇报链路 |
| M4-5 | 项目级权限 | 多租户 + 项目级 + 角色（成员/管理员），MVP 不做数据源级权限 |
| M4-6 | 用户校订闭环 | 阶段3/5/6 用户介入操作全部实现，对应智能体协作规格 §10.5 |
| M4-7 | Beta 开放 | 50-100 外部 Beta 用户，定价策略初探 |

**关键依赖**：
- M3 全部交付物就绪
- 文档导出引擎选型（依赖外部组件）

**验收准则**：
- 端到端研究耗时：标准档位 ≤ 12 分钟（`[待确认]`）
- 成本展示延迟 ≤ 3 秒
- 报告导出 Word/PDF 格式与在线版内容一致（偏差 ≤ 1%）
- 用户操作（暂停/追问/剔除/打回）经由 Orchestrator 调度，审计日志完整
- Beta 用户周活跃留存 ≥ 30%（`[待确认]`）

### M5 · 私域能力（6 周）

**目标**：开放私域能力，启动企业版转化。这是 PRD "私域优先加权"决策的落地阶段。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M5-1 | 文档上传连接器 | 用户上传 PDF/Word/Markdown/Excel 等，自动入库并可被检索 |
| M5-2 | 数据血缘标注 | 报告中显式区分"内部材料 vs 外部信源"，每条引用标注来源类型 |
| M5-3 | 数据源级权限 | 单个文档/连接器可设可见范围；按角色脱敏（如投资研究不跨部门共享） |
| M5-4 | 信源优先级 | 私域材料权重高于公域（可配置），影响结论可信度评分 |
| M5-5 | 企业版 Beta | 与 3-5 家企业客户联调试用，签署 NDA 与试用协议 |
| M5-6 | 合规基线 | 权限矩阵、审计日志、数据脱敏规则文档化（先满足 SOC 2 雏形要求） |

**关键依赖**：
- M4 全部交付物就绪
- 企业客户对接、法务合规评审
- 私域文档解析能力（PDF/Word/表格）

**验收准则**：
- 一次研究可同时引用私域材料与公域信源，报告内区分标注
- 数据源级权限可正确隔离不同角色用户对同一份报告的访问范围
- 审计日志记录每一次数据访问与报告生成，可回放
- 企业版 Beta 客户成功完成至少 1 次端到端研究试用并出具反馈报告

**目标**：SaaS GA 开放公测，把产品变成可持续运营的服务；同步输出私有化技术白皮书作为长期能力背书。

**关键交付物**：

| # | 交付物 | 说明 |
|---|---|---|
| M6-1 | SaaS GA 开放 | 公测版本上线，全量功能对企业开放 |
| M6-2 | 运营化体系 | 用户支持链路、问题响应 SLA、运营监控与告警 |
| M6-3 | SLA 制定 | 公开 SLA 承诺（可用性、响应时间、token 配额），纳入服务协议 |
| M6-4 | 私有化技术白皮书 | 描述架构已为私有化预留的关键能力点（数据本地化、模型可替换、权限深度、审计导出），作为销售材料 |
| M6-5 | V2 路线图草案 | 基于 GA 反馈形成 V2 需求草案（私人化 GA、报告校订闭环深化、第三方数据源对接等） |

**关键依赖**：
- M5 全部交付物就绪
- 法务对服务协议与 SLA 的审核
- 私有化白皮书评审（架构 + 安全 + 法务）

**验收准则**：
- 公测版本满足 SLA 承诺（可用性 ≥ 99.5%，`[待确认]`）
- 运营监控覆盖核心指标（用户活跃、研究成功率、token 消耗、SLA 达成率）
- 私有化技术白皮书通过架构 + 安全 + 法务三方评审
- PRD 验收项 A1-A14 全部通过，PRR（产品就绪评审）通过

## 4. 依赖与风险

### 4.1 关键依赖

| 类型 | 依赖项 | 影响里程碑 | 应对 |
|---|---|---|---|
| 外部 | 模型供应商账号与合同 | M0 | M0 第 1 周锁定供应商；准备备选 |
| 外部 | 公域检索抓取能力 | M1 | 自研爬虫或第三方 API，备选方案至少 2 家 |
| 外部 | 文档解析能力（PDF/Word） | M5 | M4 启动技术选型 |
| 外部 | 法律合规评审（数据采集、用户协议） | M3 末、M6 | M2 末启动法务对接 |
| 团队 | 至少 1 名前端 + 1 名后端 + 1 名全栈 | M0 起 | 关键岗位不可缺 |
| 团队 | 算法/Agent 调优经验 | M2 起 | 内部培养或外部顾问 |
| 团队 | 设计与运营支持 | M3 起 | 兼职或外部合作 |

### 4.2 风险矩阵

| # | 风险 | 概率 | 影响 | 缓解策略 |
|---|---|---|---|---|
| R1 | 模型能力不足以满足研究质量要求 | 中 | 高 | M1 末做模型能力基准评估；预留多模型供应商切换能力 |
| R2 | 多智能体编排技术风险延后暴露 | 中 | 高 | M0 末做技术 spike 验证 Agent 编排框架适配性 |
