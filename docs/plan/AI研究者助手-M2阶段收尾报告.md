## 3. 关键技术演进（M1→M2）

1. **检查点持久化与 HITL 闭环**（M2-2）：`InMemorySaver` → 应用级 `AsyncPostgresSaver`（thread_id=run_id），澄清答案与冲突裁决跨请求/跨进程恢复；executor 统一「DB 乐观翻转 + checkpoint Command(resume)」双轨。
2. **过程数据全面落库**（M2-4/5/6）：六阶段行、子问题、证据（含域名规则五值信源元数据）、run_interventions、五动作审计全程可回放，看板 WS/REST 轮询/重连三态一致。
3. **数据点级溯源**（M2-7）：报告从四段 Markdown 升级为 reporter LLM blocks 计划 + 确定性绑定引擎——marker 仅被引占号、snippet 原文回退、缺源降级 inferred、数字断言一次自修复否则剔除、dispute 确定性注入；终稿 status=final + report_citations block 粒度。
4. **执行位置迁移到 Celery + Redis**（M2-8b）：研究/恢复从 API 进程 `create_task` 迁到独立 worker；双态 RealtimeHub（内存/Redis Pub/Sub PSUBSCRIBE 桥接）、`lease:run` NX 租约 + 独立心跳、`control:run` 只升不降信号、worker 首任务前孤儿三类清扫（挂起→paused/报告收敛/RUN_WORKER_LOST/pending 重投）；任务幂等（重投递 NX 失败即退出）、瞬时故障有限重试（max_retries=2）。
5. **可观测性收口**：M2-8a A8 指标（成功率/介入率/溯源率双口径）+ M2-8b 执行可观测（owner/lease 镜像列、孤儿审计 `run.orphan_recovered`）+ LLM usage 零值 warning，成本失聚可定位。

## 5. 遗留项与 M3 启动条件

### 5.1 不阻断 M3 的技术挂账

| 项 | 性质 | 建议处置时机 |
| --- | --- | --- |
| worker 任务级装配冷启动 10-15s（drvfs 下 LLM 模块冷导入） | 性能优化，正确性不受影响 | M3 内做进程级常驻 loop/连接池化 |
| Celery beat 周期清扫、多 worker 水平扩展 | 非 MVP 目标（SDP §1.4） | M6 运营化 |
| 前端 `report.chunk/report.finished` 死类型与 mock 发射点 | M2 未实现帧的枚举残留（后端文档已标注挂 M4） | 前端择期清理 |
| 看板「已用时长」含暂停墙钟 | 产品口径问题，非 bug | 产品确认口径；如扣暂停用 audit pause/resume 配对即可，零迁移 |

### 5.2 进入 M3 必须新建的工程缺口（SDP §3 M3 交付物对照）

1. **M3-5 运营体系（最大块）**：当前仅 seed 账号 + 登录，`/users`、`/teams` 为占位——缺注册/邀请、成员管理、研究者/管理员/审批人三角色权限、反馈通道 API。
2. **M3-4 模板管理**：当前仅硬编码 generic，`/templates` 占位——缺模板 CRUD + 1 个示范领域模板（技术调研/竞品分析）。
3. **M3-3 档位参数化**：四档 token 预算已有，缺检索轮数/深度端到端生效与研究前成本预估（承载 A6 正式验收）。
4. **M3-1 整合收尾**：冲突「可筛选查看」（A4）、证据不足显式提示边界样例（A9）、项目内成员共享、A10 ≤15 分钟硬指标专项（实测标准档 40s~1min 级，风险低）。
5. **M3-2 公域限定**：天然满足（无私域连接器），保持占位不启用。

### 5.3 非技术前置（需产品/运营）

- 种子用户名单（5-10 人）与试用协议、反馈收集机制（工单+调研）；
- SDP §7 标定项：档位 token 具体数值（现已有实测可标定）、≤15 分钟耗时口径确认、批判收敛率基线。

## 6. 结论

M2 按「技术风险优先」完成了从 M1 可演示 demo 到**可内部试用工程形态**的全部既定能力：六阶段链路具备 HITL 恢复、透明看板、成本治理、数据点级溯源、指标出数与跨进程生产执行；契约、迁移、门禁、真链、交接文档五条线闭合，无阻断性遗留。技术上可以启动 M3；M3 的主要工程量从「编排/链路」转向「账号权限/模板/运营体系」等产品化能力，建议先出 M3 阶段技术方案并与产品确认 §5.3 标定项后按包推进。
